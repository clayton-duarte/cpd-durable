# pi-durable feature inventory

Inventory of **`@earendil-works/pi-durable` 1.5.2**, pinned in this repository, inspected on 2026-11-17. The SDK is experimental; capabilities on upstream `main` can differ from this release. This inventory is a capability map, not an implementation commitment or authorization to enable tools or a fixed agent hierarchy.

Evidence: the published package's [README](https://unpkg.com/@earendil-works/pi-durable@1.5.2/README.md), [public exports](https://unpkg.com/@earendil-works/pi-durable@1.5.2/dist/index.d.ts) and [package manifest](https://unpkg.com/@earendil-works/pi-durable@1.5.2/package.json), checked against our server, presentation schema and client. SDK claims below are documentation/API evidence, not independent tests of every feature. See [our verification boundaries](../README.md#checks).

## Reading the status

- **Exposed:** the current chat offers this behavior.
- **Underlying:** the SDK supplies it behind the current chat, but no dedicated UI/control exposes it; some behavior is an SDK default, not exercised by our tests.
- **Not integrated:** application wiring, UI, permissions or dependencies would be needed.

The current app has an original conversation and independently created chats, with server-configured OpenCode Go model/thinking choices and native coding-tool execution. [Server setup](../src/server/chat.ts), [chat catalog](../src/server/chats.ts), [execution environment](../src/server/execution.ts), [HTTP/SSE endpoints](../src/server/app.ts), [presentation filtering](../src/server/presentation.ts) and [client](../src/client/chat.tsx) are implementation evidence. The [component mapping](chat-components.md) records presentation semantics; the [pi TUI parity section](#pi-tui-parity) records the expanded authorization and remaining gaps.

Durability has limits: partial progress can be shown before its deferred persistence window closes; SQLite uses WAL with `synchronous = NORMAL`, so process-crash recovery is not a power-loss guarantee. The SDK requires one writer per storage; the app obtains its fixed loopback listener before opening writable storage. Cancelling observation/waiting does not itself cancel work. Preserve these distinctions in new UI controls.

## Candidate enrichment, not a selected backlog

For discussion, the closest additions to the existing single-chat boundary are:

1. Earlier-history loading/gap recovery is implemented; clearer submission/run status remains a candidate.
2. Usage/cost display, followed by honest context/compaction visibility.
3. Provider reasoning display is wired through the supplied Reasoning element; model/thinking controls and global role assignments are exposed, while broader settings remain unimplemented.

Continue, reset and busy-input queue/steer choices are now exposed with the [documented semantics](chat-components.md#2-composer-and-run-controls). The remaining items above are candidates, not authorization.

The [pi TUI parity authorization](#pi-tui-parity) expands the implementation agenda. [Global model assignments](design.md#native-execution-and-pi-tui-parity) are implemented as described above; saved tangent and worker assignments do not by themselves implement those workflows.

## pi TUI parity

The User authorized broad pi-TUI feature parity on 2026-11-17, with `~/` as the default directory, normal host OS permissions, and no cpd-added approval prompts or sandbox restrictions. Authorization is not an assertion that every feature is implemented. Model/thinking selection now uses configured server-side choices; no separate coding-agent runtime is introduced.

Comparison evidence: pi's [interactive usage](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/usage.md) and [tool exports/defaults](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/tools/index.ts), inspected 2026-11-17 on upstream `main`; this is a moving reference, not a tested claim about every release or optional extension.

Tool arguments/output are expected private conversation data and can contain paths or secrets; provider diagnostics and arbitrary SDK documents are still not dumped into the browser.
